# План реализации — Спека 0001 (фаза 1)

- **Статус:** черновик плана (спека согласована 17 окт)
- **Порядок веток:** сначала `south_edition` (основная работа), затем перенос
  общих файлов варианта в `dev-darktec` (без экрана настроек — он появится в
  фазе 1b). Сайт — параллельно, репо `beeline09.github.io`.
- **Железный принцип:** ноль правок ядра (FR-30). Каждое место, где хук не
  получается, останавливает этап и выносится на согласование.

## Этап 0. Инструменты таблиц SOC (FR-20, D-3)

1. `tools/gen_darktec_soc_tables.py` — вход: CSV замеров (формат как у
   LiION_4000_*.csv); выход: заголовочный файл с массивами
   `{soc_pct, cell_mv}` на химию (шаг ≤ 25 мВ, монотонность проверяется
   скриптом), в заголовке — источник, дата, версия формата.
2. Li-ion — из замеров MacMillan25 (разрядная кривая как OCV-опора).
   LiFePO4/LTO — стартовые точки из открытых источников §8 спеки, помечены
   `approximation`.
3. Native-тест в `test/`: контрольные точки Li-ion (10+ из CSV), граничные
   точки LiFePO4/LTO (AC-9).

## Этап 1. Хранилище DarktecPrefs (FR-14..19, D-7)

1. `variants/darktec/DarktecPrefs.h/.cpp` — файл `/darktec.prefs` в
   `InternalFS`: магия `DRTC`, версия, поля (capacity uint16, chem uint8,
   cells uint8, module uint8, charge_ma uint16, резерв), CRC16.
2. **Ленивая инициализация** (D-7): первый доступ после готовности ФС; точку
   вызова фиксируем первым делом этого этапа — кандидат: инициализация в
   начале `UITask`-оверлея / `main()`-хука варианта, но **не** в
   `DarktecBoard::begin()` (раньше `InternalFS.begin()`). Если готовой точки
   нет — минимальный вызов из уже существующего кода варианта, который
   выполняется после `InternalFS.begin()`; если и это невозможно — согласуем.
3. Ошибка ФС → работа на дефолтах флагов, без записи, загрузка не
   блокируется. Запись — временный файл + rename.

## Этап 2. SOC-модель (FR-20..23, FR-25..27, D-1..D-4)

1. `variants/darktec/DarktecSoc.h` — чистая функция
   `(V, I, coulomb_state, prefs) → SOC`, без обращений к железу:
   таблица + R-компенсация (D-1: 60/40/30 мОм) + кулонометр (D-2: покой
   |I|<10 мА/5 мин, коррекция ≤ 5 %/час; D-4: SYSTEMOFF → переоценка при
   загрузке) + захват температуры (FR-24, EMA, ≤ 2 Б).
2. Интеграция: место съёма V/I — существующий опрос батареи варианта (где
   сейчас считается процент); INA3221 недоступен → табличный режим.
3. Все потребители процента (экран, значок) переключаются на новый SOC;
   формат телеметрии прежний (FR-25).
4. Native-тесты автомата SOC и функции (AC-7/AC-8/AC-9).

## Этап 3. Автомат заряда (FR-34)

1. `DarktecChargeState` — чистый автомат (idle/charging/full): пол 30 мА,
   гистерезис 15 мА, EMA 2–5 с; full = V ≥ V_full−ε и I < C/30, N минут.
2. Интеграция хуками: молния, «не гасить экран на зарядке», направление
   кулонометра — из состояний автомата. Существующие места детекции
   (захардкоженные 120 мА) в коде варианта заменяются на автомат.
3. Native-тесты переходов (AC-13).

## Этап 4. Экран настроек юга (FR-8..13, FR-32)

1. Разведка (первый таск этапа): как встроить пункты в экран настроек юга
   хуком (перехват отрисовки/навигации). Если хук невозможен — фиксируем
   минимальную правку ядра и согласуем до кода.
2. Пункты: «Ёмкость АКБ, mAh» (±100, 500–30000), «Тип АКБ» (химия),
   «Ячеек» (1/2, валидация LTO-only), «Радиомодуль» (просмотр/смена),
   «Ток заряда, mA» (±100, 100–3000). Химия/ячейки/модуль — применяется
   после перезагрузки (D-8: подсказка в UI).
3. Сохранение — только в DarktecPrefs; после сохранения — перезагрузка по
   запросу пользователя (или автоматическая, решить на месте).

## Этап 5. Флаги сборки и CI (FR-1..3, FR-31)

1. `battery_chemistry.h`: `BATTERY_CAPACITY_MAH` (500..30000), 
   `DARKTEC_CHARGE_CURRENT_MA` (100..3000); `DARKTEC_RADIO_MODULE` enum
   (HT_RA62/E22_900M30S/E22P_868M30S/E22_900M33S) — таблица пинов из
   текущей распиновки (D-6); валидации `#error` (в т.ч. химия×ячейки).
2. Скрипты `build-darktec-matrix.sh` / on-demand принимают новые флаги;
   дефолты CI не меняются (FR-7).

## Этап 6. Сайт (FR-4..6, FR-33)

1. `beeline09.github.io` → `darktec/`: поля «Ёмкость ячейки, mAh» (500–30000,
   шаг 100), «Радиомодуль» (селектор), «Ток заряда, mA» (100–3000); подсказка
   у тока про перепайку делителя; localStorage; параметры → on-demand сборка
   и ключ кэша; валидация «Ячеек» на клиенте (2 только для LTO).
2. Проверка: сборка через CI с новыми параметрами, артефакты скачиваются.

## Этап 7. Приёмка (AC)

1. Прошивка юга на плату (Li-ion 1S): AC-1, AC-3, AC-4, AC-7, AC-11.
2. Зарядный цикл на плате: AC-13 (молния/состояния/гистерезис).
3. On-demand сборки с сайта: AC-2, AC-13 (номинал 1000).
4. Перепрошивки юг↔официалка: AC-5, AC-6.
5. CI обеих веток зелёные; дифф ядра — ноль: AC-10, AC-11.
6. Отчёт владельцу с таблицей AC → результат.

## Риски

- Точка ленивой инициализации ФС (этап 1) — если готовой нет, эскалация.
- Экран настроек хуком (этап 4) — если хук не выходит, эскалация.
- R_cell 60/40/30 мОм — approximation; после этапа 7 замер sag на плате
  уточнит (обновление констант — отдельный микрокоммит).

## Фаза 1b. Официальная прошивка (FR-28/29)

Реализация — целиком оверлеем варианта, **правок ядра — ноль**:

1. Вариант: DarktecSocTables.h, DarktecSoc.h, DarktecSocModel.h,
   DarktecPrefsFormat.h/.cpp, DarktecPrefs.h, DarktecPowerState.h — копии
   из южной ветки (формат файла тот же, FR-16). BatteryPack-оверлей не
   нужен: в ядре официалки helpers/BatteryPack нет, SOC-процент идёт
   прямо из DarktecPowerState в оверлейный UI.
2. battery_chemistry.h — добавлены флаги BATTERY_CAPACITY_MAH /
   DARKTEC_CHARGE_CURRENT_MA с #error-валидацией (защита DARKTEC_BATT_PROTECT
   в официалку сознательно не переносится — вне скоупа фазы).
3. variant.h — DARKTEC_RADIO_MODULE (0..3) с валидацией; для E22P (2)
   SX126X_RXEN снимается #undef и пин P0.17 держится высоким из
   DarktecBoard::begin() (EN-логика MacMillan25).
4. DarktecBoard.h/.cpp — readBattMvRaw, ленивый DarktecPrefs::begin(),
   тик SOC-модели и автомата заряда из pollChargeSense (старые пороги
   120/100 мА удалены), фасад DarktecPowerState.
5. Экран настроек (FR-29): страница DARKTEC_PAGE в оверлее
   variants/darktec/companion_ui/UITask.cpp (этот оверлей уже существовал
   для юг-независимых правок UI и подменяет ui-new/UITask.cpp фильтром
   в env'ах companion). Та же страница, что на юге: Capacity/Batt type/
   Cells/Radio mod/Charge, строки английские; SOC-процент индикатора —
   из модели. Оверлей невозможен только там, где его не было и в фазе 1
   на юге: сам факт новой страницы требует файл-подмены — он уже
   вариантный, новых мест правки ядра не появилось.
6. Скрипт scripts/build-darktec-ondemand.sh — токены __cap/__mod/__chg
   (только не-дефолты, порядок как на сайте), DarktecOff_-нейминг,
   ADC/CAP/MOD/CHG в DEFS_H. Workflow main уже шлёт эти параметры.

Проверки: Darktec_companion_radio_ble/usb SUCCESS; прошивка официалки
на устройство; имена сайт↔скрипт сверены байт в байт.

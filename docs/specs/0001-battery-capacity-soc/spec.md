## 1. Контекст и проблема

Сейчас процент батареи в варианте Darktec считается линейной шкалой напряжения
от `BATT_CELL_EMPTY_MV` до `BATT_CELL_FULL_MV` (`variants/darktec/battery_chemistry.h`).
Замеры реальной ячейки Li-ion 4000 mAh (MacMillan25, `~/Downloads/LiION_4000_*.csv`)
показывают, что линейная шкала фундаментально неверна:

| Факт из замеров | Следствие для расчёта |
|---|---|
| Заряд 2 А (0.5C) и разряд 0.1 А: при одном и том же SOC 50% напряжение отличается на ~390 мВ (≈3.99 В против 3.60 В) — падение на внутреннем сопротивлении и поляризация | Одна таблица V→% без учёта тока не может быть верной для заряда и разряда одновременно. Отсюда «ложные 100%» при заряде |
| Разряд: плато ≈3.88→3.47 В покрывает 20–80 % SOC | Линейная шкала висит на «80%» половину разряда, затем резко падает |
| Заряд: CC-фаза до 4.2 В — 74 мин (2540 mAh из 4133), затем CV-фаза 2 ч с плавным спадом тока 2.0→0.13 А | Заряд нельзя считать линейно по напряжению: почти весь заряд идёт «в плато» |
| Ёмкость цикла: заряд принял 4133 mAh, разряд отдал 3690 mAh (КПД ≈ 89 %) | Замеры согласованны (36.9 ч × ~0.1 А), пригодны как эталон Li-ion таблицы |

Дополнительно:
- ёмкость ячейки — личный параметр владельца, прошивка её не знает;
- плата Darktec выпускается с разными радиомодулями (HT-RA62, E22-900M30S,
  E22P-868M30S, E22-900M33S), поведение радио и потребление у них разные —
  конфигурация модуля должна быть параметром, а не только химией/ёмкостью;
- параметры, заданные при сборке, владелец не может поменять без перепрошивки.

## 2. Цели

1. Точный (не линейный) расчёт SOC для трёх химий: Li-ion, LiFePO4, LTO —
   с учётом направления (заряд/разряд) и тока.
2. Ёмкость ячейки, тип АКБ (химия), число ячеек и тип радиомодуля — параметры:
   задаются при сборке с сайта, меняются владельцем на устройстве через
   настройки, переживают перезагрузку и перепрошивку.
3. Минимальное вмешательство в код прошивки: всё, что можно — хуками и
   оверлеями варианта (как делали раньше: молния зарядки, LED-точка).
4. Фундамент для фазы 2 — экран ETA (время работы / до полной зарядки).

## 3. Не-цели (вне этой спеки)

- Экран ETA и формулы отображения времени — **фаза 2**, отдельная спека.
- Пороги защиты по умолчанию не меняются (меняется только источник химии,
  из которого защита берёт пороги — см. FR-27).
- Температурная компенсация SOC — **фаза 2**, источник уже определён:

  телеметрии) — см. FR-24 и D-9. В фазу 1 входит только сбор сглаженного
  значения, без применения к таблицам.
- Формат телеметрии для мобильного приложения — не меняем.
- Личный тулинг из ветки MacMillan25 (build-local, git_push.py) — не переносим.

## 4. Термины

- **Ячейка (cell)** — одиночный аккумулятор. **Пакет (pack)** — подключённое
  к плате: 1S для Li-ion/LiFePO4, 1S–2S для LTO.
- **Ёмкость** задаётся **на ячейку** (mAh); при последовательном соединении
  ёмкость пакета равна ёмкости ячейки, SOC общий.
- **SOC** — state of charge, процент. **OCV** — напряжение покоя.
- **CC/CV** — профиль заряда: постоянный ток, затем постоянное напряжение.
- **Хук/оверлей** — код варианта, встраивающийся в UI/логику без правки
  файлов ядра (переопределение классов, `-I` путь к своему файлу раньше
  одноимённого, пост-обработка отрисовки).

## 5. Пользовательские истории

- **US-1 (сборка с сайта):** как владелец, я указываю на сайте ёмкость ячейки
  и тип установленного радиомодуля — прошивка соответствует моей плате.
- **US-2 (смена на устройстве):** как владелец, я меняю ёмкость (±100 mAh),
  тип АКБ и число ячеек в настройках без перепрошивки; значения сохраняются.
- **US-3 (доверие к проценту):** процент монотонно растёт на заряде (включая
  медленную CV-фазу) и плавно падает на разряде — без заливаний и скачков.
- **US-4 (перепрошивка):** прошиваю официальную поверх южной и обратно —
  устройство стартует, мои параметры (ёмкость, химия, ячейки, модуль) читаются.
- **US-5 (химии):** как владелец LiFePO4/LTO я получаю честный процент
  с учётом особенностей моей химии; смена химии в настройках обновляет и
  пороги защиты (юг) после перезагрузки.
- **US-6 (валидность):** система не даёт выбрать недопустимую комбинацию
  (например 2 ячейки с Li-ion).

## 6. Функциональные требования

### Сборка (флаги)

- **FR-1.** Флаг `BATTERY_CAPACITY_MAH` — ёмкость одной ячейки, mAh,
  по умолчанию `4000`. Валидация при сборке: `500..30000` (большие LTO и
  LiFePO4-ячейки), иначе `#error`.
- **FR-2.** Флаг `DARKTEC_RADIO_MODULE` — тип радиомодуля, enum:
  `0 = HT_RA62` (голый SX1262), `1 = E22_900M30S` (по умолчанию),
  `2 = E22P_868M30S`, `3 = E22_900M33S`. Значение управляет поведением
  радио-обвязки варианта; таблица «значение → пины (RXEN/EN/DIO2)» выводится
  из текущей распиновки варианта в `plan.md`: HT_RA62 — текущее поведение без
  изменений (проверено работой), E22P/E22-33S — по находкам MacMillan25
  (EN держится высоким). Наш enum — базовый интерфейс: внешние ветки
  (включая ветку MacMillan25) принимают его как основу.
- **FR-3.** Существующие флаги химии/ячеек (`BATTERY_CHEMISTRY`,
  `BATTERY_CELLS`) остаются; их смысл смещается: они задают **дефолт**, который
  попадает в файл настроек при первом старте (см. FR-16).

### Сайт (beeline09.github.io/darktec)

- **FR-4.** В «Предопределённых параметрах» добавляется поле **«Ёмкость
  ячейки, mAh»**: число, шаг 100, диапазон 500–30000, по умолчанию 4000,
  хранится в localStorage как остальные параметры, уходит в on-demand сборку
  как `-DBATTERY_CAPACITY_MAH=...` и в ключ кэша.
- **FR-5.** Там же добавляется селектор **«Радиомодуль»**: HT-RA62 /
  E22-900M30S / E22P-868M30S / E22-900M33S; по умолчанию E22-900M30S; уходит
  в сборку как `-DDARKTEC_RADIO_MODULE=...` и в ключ кэша.
- **FR-33.** Там же добавляется поле **«Ток заряда, mA»**: число, шаг 100,
  диапазон 100–3000, по умолчанию 2000; localStorage; в on-demand сборку как
  `-DDARKTEC_CHARGE_CURRENT_MA=...` и в ключ кэша. Подсказка у поля: «Номинал
  зарядного тока вашей платы (задаётся резисторным делителем; после перепайки
  измените и в настройках устройства)».
- **FR-6.** Селекторы «Тип АКБ» (химия) и «Ячеек» уже есть на сайте — остаются;
  их значения тоже задают дефолт файла настроек.
- **FR-7.** Обычные (не on-demand) сборки CI используют дефолты; изменение
  дефолтов — только через коммит в репо.

### Настройки на устройстве (южная прошивка, фаза 1)

- **FR-8.** В настройки добавляется пункт **«Ёмкость АКБ, mAh»**: показывает
  значение из файла настроек Darktec (первое значение — из флага сборки),
  меняется шагом ±100 mAh, диапазон 500–30000, сохранение при выходе.
- **FR-9.** Пункт **«Тип АКБ»**: Li-ion / LiFePO4 / LTO; применяется после
  перезагрузки (влияет на таблицы SOC и пороги защиты).
- **FR-10.** Пункт **«Ячеек»**: 1 или 2. Валидация на устройстве: 2 доступна
  только для LTO (US-6); при смене химии на не-LTO с сохранёнными 2 ячейками
  значение принудительно возвращается к 1 с показом предупреждения.
  Применяется после перезагрузки.
- **FR-11.** Пункт **«Радиомодуль»**: показывает тип модуля из настроек;
  изменение применяется после перезагрузки (влияет на радио-обвязку).
- **FR-12.** Все пункты встраиваются в навигацию существующего экрана
  настроек; реализация — **приоритетно хуками/оверлеем варианта** (см. FR-22);
  если хук невозможен, минимальная правка экрана допускается только по
  согласованию в плане.
- **FR-13.** Локализация — кириллицей, как остальной UI южной прошивки.

### Хранилище параметров Darktec (обе прошивки)

- **FR-14.** Параметры варианта хранятся в **собственном файле** Darktec
  (например `/darktec.prefs`) в той же внутренней файловой системе, где ядро
  хранит свои prefs (`InternalFS`, LittleFS — доступен варианту как глобальный
  `InternalFS` из `main.cpp`; проверено: `DataStore` использует ту же ФС).
  Структура файла: магия `DRTC`, версия формата, поля (ёмкость mAh — uint16,
  химия — uint8, ячейки — uint8, модуль — uint8, ток заряда платы — uint16
  (FR-31), резерв), контрольная сумма.
  Структура `NodePrefs` ядра **не изменяется**.
  Инициализация файла — **ленивая**, при первом доступе после готовности ФС
  (осторожно: `DarktecBoard::begin()` может выполняться раньше
  `InternalFS.begin()`); точку вызова фиксирует `plan.md`. При недоступной
  ФС — работа на дефолтах флагов без записи (загрузка не блокируется).
- **FR-15.** Файл создаётся при первом старте с дефолтами из флагов сборки
  (FR-1/2/3); далее источник истины — файл.
- **FR-16.** Формат файла одинаков в южной и официальной ветках → перепрошивка
  в обе стороны сохраняет параметры пользователя (US-4).
- **FR-17.** Версионирование: старая прошивка, не знающая файл, его просто не
  читает; новая прошивка читает файлы своей и старших версий по возможности
  (незнакомые поля игнорируются). Даунгрейд не ломает загрузку.
- **FR-18.** Factory reset ядра (формат ФС) стирает и файл Darktec —
  параметры возвращаются к флагам сборки; это желаемое поведение.
- **FR-19.** Запись файла — редкая (изменение пользователем), износ LittleFS
  не является риском; запись атомарная (запись во временный файл + rename,
  насколько позволяет API).

### Расчёт SOC (обе прошивки)

- **FR-20.** SOC по нормализованным таблицам «напряжение покоя ячейки ↔ SOC»
  (мВ, шаг ≤ 25 мВ) — по одной на химию, в `variants/darktec`. Li-ion — из
  замеров MacMillan25; LiFePO4/LTO — из открытых данных, помечены
  «approximation» (§8). Таблицы **генерируются скриптом** из CSV (в `tools/`,
  по образцу подхода MacMillan25) — новые замеры от любого владельца
  подмешиваются регенерацией; в заголовке таблицы — источник, дата и версия
  формата.
- **FR-21.** Компенсация тока: `V_corr = V + I_batt · R_cell` (заряд «+»,
  разряд «−»), `I_batt` — ток канала батареи INA3221, `R_cell` — константа по
  умолчанию на химию: средние типовые значения из открытых источников —
  Li-ion ≈ 60 мОм, LiFePO4 ≈ 40 мОм, LTO ≈ 30 мОм (approximation, для
  потребительских ячеек; уточнение замером sag под известным током — в
  плане; флаг переопределения `-DBATTERY_CELL_RESISTANCE_MOHM` — в плане).
- **FR-22.** Кулонометр: интегрирование тока INA3221 (ΔSOC = ΔmAh / ёмкость),
  дрейф-коррекция по напряжению в покое; «покой» — |I| < 10 мА непрерывно
  5 минут (стартовые значения, уточняются на железе), скорость коррекции
  ограничена (≤ 5 % SOC/час), чтобы не было скачков. Без INA3221 — деградация
  до табличного расчёта. После SYSTEMOFF (гибернация юга) счётчик не имеет
  смысла: при загрузке SOC переоценивается по таблице из напряжения; во время
  лёгких снов интегрирование продолжается.
- **FR-23.** На CV-фазе заряда SOC досчитывается кулонометром до 100% при токе
  ≈ C/30 — без «залипания» на 95%+.
- **FR-24.** Кулонометр захватывает сглаженную температуру платформы
  (`getTemperature()` nRF52840 — температура кристалла, EMA с постоянной
  времени порядка десятков минут, без учёта кратковременных всплесков от TX)
  и хранит её в состоянии (≤ 2 Б RAM). В фазе 1 значение только собирается и
  логируется для будущей калибровки; к таблицам SOC не применяется
  (температурная компенсация — фаза 2, D-9).
- **FR-25.** Один SOC везде (экран, значок); формат телеметрии не меняется.
- **FR-26.** LTO 2S: таблицы на ячейку, напряжение пакета / `BATTERY_CELLS`.
- **FR-27.** Runtime-химия из файла настроек является источником и для порогов
  южной ADC-защиты: код защиты живёт в варианте (`DarktecAdcPower`), поэтому
  ядро не затрагивается; при смене химии пороги применяются после
  перезагрузки вместе с таблицами.

### Принцип минимального вмешательства

- **FR-30.** Везде, где возможно, изменения UI и поведения — **хуками и
  оверлеями варианта** (как молния зарядки и LED-точка раньше). Правки файлов
  ядра допускаются только если хук объективно невозможен; каждое такое место
  перечисляется в `plan.md` и согласуется владельцем отдельно до реализации.

### Зарядная цепь платы (информационный параметр)

Аппаратный факт: контроллера заряда на плате нет — заряд выполняет
понижающий DC-DC **TPS54302** с дискретной петлёй CC/CV; зарядный ток задаётся
резисторным делителем и владелец может его перепаять. Автотерминации нет:
зарядник держит CV бесконечно, момент «100%» определяет только прошивка
(FR-23, правило C/30 — на кривой замеров 133 мА сходится с фактическим
плато-током 0.13 А).

- **FR-31.** В файле настроек хранится **«Ток заряда платы, mA»**
  (uint16): фактический ток CC-фазы для данной платы. Дефолт — из флага
  `DARKTEC_CHARGE_CURRENT_MA` (по умолчанию 2000 — по замерам MacMillan25);
  после перепайки делителя владелец обновляет значение. Диапазон 100–3000
  (потолок TPS54302 — 3 А). Параметр информационный: прошивка ток не
  управляет; используется для правила термин C/30 (FR-34) и ETA заряда
  (фаза 2), к детекции заряда отношения не имеет.
- **FR-32.** В настройках (фаза 1, рядом с ёмкостью) — пункт **«Ток заряда,
  mA»**: шаг ±100, диапазон 100–3000, сохранение в тот же файл; дефолт — из
  флага сборки (в т.ч. заданного на сайте, FR-33).

### Детекция заряда (автомат)

- **FR-34.** Детекция заряда — конечный автомат `idle → charging → full`
  (только код варианта; ядро не трогается):
  * **charging** — ток батареи по INA3221 (сглаженный EMA ~2–5 с) в сторону
    заряда выше абсолютного порога входа (~30 мА); выход из charging при
    спаде ниже порога выхода (~15 мА, гистерезис). От номинального тока
    заряда (FR-31) детекция НЕ зависит — после перепайки делителя на любой
    ток детекция работает.
  * **full** — V ≥ (V_full − ε) И ток < C/30 (C — ёмкость из FR-8,
    коэффициент 30) непрерывно N минут → «полная»: молния гаснет,
    SOC = 100%. Это же чинит существующую вечную молнию (зарядник без
    контроллера не отсекается никогда — FR-31). Выход из full: ток выше
    C/30 (новая CC-фаза) → charging; просадка напряжения → idle;
    CV-подпитка между exit-порогом и C/30 — остаёмся в full.
  * Коэффициенты (пол, гистерезис, ε, N) фиксируются в `plan.md` и
    подбираются на железе; автомат — чистая функция для native-тестов
    (NFR-4). Молния, «не гасить экран на зарядке» и направление кулонометра
    питаются из состояний автомата.


## 7. Нефункциональные требования

- **NFR-1.** Память: таблицы трёх химий суммарно ≤ 512 Б flash; состояние
  кулонометра ≤ 32 Б RAM; файл настроек ≤ 64 Б. Сборки не приближаются к
  потолку flash/RAM ближе 5 п.п. к текущим значениям (юг: Flash 66.5%,
  RAM 71.5%).
- **NFR-2.** Права на правку ядра: по умолчанию — ноль правок; исключения
  только через FR-29 (хук невозможен → план → согласование). Персистентность
  ядра (NodePrefs) не затрагивается вообще (FR-14).
- **NFR-3.** Стиль кода и комментарии — как в существующих файлах варианта
  (русские комментарии, clang-format).
- **NFR-4.** Расчёт SOC детерминирован и юнит-тестируем: чистая функция
  «(V, I, счётчики) → SOC»; native-тесты в `test/`, контрольные точки —
  из CSV MacMillan25 (Li-ion) и табличных точек LiFePO4/LTO.
- **NFR-5.** Ни одна существующая настройка пользователя не теряется.

## 8. Справочные данные по химиям

### Li-ion (эталон — замеры MacMillan25, 4000 mAh, 25 °C)

- Заряд: CC ~2 А до 4.20 В (74 мин, ~62% ёмкости), затем CV 4.205 В, спад тока
  до 0.13 А; заряд принял 4133 mAh за ~3.1 ч (автотерминации нет — FR-31).
- Разряд ~0.1 А за 36.9 ч: плато ≈3.88→3.47 В (20–80 % SOC), колено ниже
  3.4 В, отсечка 3.0 В; отдача 3690 mAh (КПД цикла ≈ 89 %).
- Зарядная цепь платы: DC-DC TPS54302 с дискретной петлёй CC/CV, без
  контроллера заряда и без автотерминации (см. FR-31); «спад до 0.13 А» в
  замере — не отсечка зарядника, а бесконечное CV: момент «100%» определяет
  прошивка (FR-23).
- Вывод: таблица по разрядной кривой (≈ OCV), R-компенсация по FR-21.

### LiFePO4 (открытые данные, approximation)

- Плоское плато: 20–80% SOC — ~3.27–3.32 В → напряжение в середине почти
  неинформативно; основной источник SOC — кулонометр (FR-22 обязателен),
  напряжение якорит концы (100% после CV, 0% у отсечки).
- Заряд CC/CV до 3.65 В; покой полной ~3.40–3.45 В; пустой ~2.5–2.8 В.
- Источники: [EVE LiFePO4 SOC chart](https://www.evemall.eu/selection-guide/eve-lifepo4-state-charge-chart-discharge-curve-capacity-diagrams),
  [LiTime voltage chart](https://www.litime.com/blogs/battery-knowledge/lifepo4-voltage-chart),
  [TI SLUAAR1 — coulomb counting for LFP](https://www.ti.com/lit/an/sluaar1/sluaar1.pdf).

### LTO (открытые данные, approximation)

- Кривая монотонная, без длинного плато — табличный V→SOC работает лучше всех
  химий; кулонометр — уточнение.
- Окно 1.8–2.7 В; заряд обычно до 2.6–2.7 В (наш `BATT_CELL_FULL_MV` 2.50 В —
  консервативно); отсечка 1.8–1.9 В.
- Источники: [Torex LTO charging](https://product.torexsemi.com/en/technical-support/techinfo/doc_2089),
  [ResearchGate OCV-SOC LTO](https://www.researchgate.net/figure/The-OCV-SOC-characteristic-of-the-LTO-based-battery-measured-at-T-25-C_fig4_324117029),
  [MDPI incremental capacity LTO](https://www.mdpi.com/1996-1073/16/8/3434).

## 10. Критерии приёмки

- **AC-1.** Чистые настройки: в меню «Ёмкость АКБ: 4000», «Тип АКБ»/«Ячеек»/
  «Радиомодуль» — из флагов сборки; «Ток заряда: 2000».
- **AC-12.** «Ток заряда» меняется в настройках (шаг ±100, границы 100/3000),
  переживает перезагрузку; после перепайки делителя на 1 А и установки 1000
  ETA-модель фазы 2 получает корректный номинал.
- **AC-13.** Автомат заряда (FR-34): молния появляется при токе заряда
  ~30 мА и горит весь CV-хвост (в т.ч. при 50 мА); гаснет в состоянии «full»
  (V у CV-порога, ток < C/30, N минут); мигания при TX-просадках нет
  (гистерезис + EMA). Детекция не зависит от номинала: сборка с «Ток заряда:
  1000» и фактическим током 1 А — детекция и «full» работают; ночная зарядка
  завершается состоянием «full», а не вечной молнией.
- **AC-2.** On-demand сборка с сайта (ёмкость 3000, модуль E22P) → после
  прошивки в настройках 3000 и E22P; радио работает на собранном модуле.
- **AC-3.** Ёмкость 2500 меняется в настройках и переживает перезагрузку;
  шаг ±100; границы 500/30000 не преодолеваются.
- **AC-4.** Смена «Тип АКБ» на LiFePO4 → после перезагрузки процент считается
  по LiFePO4-таблице, южная защита использует пороги LiFePO4 (FR-27); «Ячеек»
  для Li-ion физически не даёт выставить 2.
- **AC-5.** Южная с изменёнными параметрами → прошить официальную: загрузка,
  параметры читаются; обратно → то же (FR-16).
- **AC-6.** Старые сборки (без файла Darktec) поверх: загрузка, ядро не тронуто
  (NodePrefs не менялся — проверка диффом), настройки ядра целы.
- **AC-7.** Заряд от ~50%: монотонный рост до 100% при токе ≈ C/30; разряд:
  плато Li-ion не «залипает»; скачков > 3% между обновлениями экрана нет.
- **AC-8.** LiFePO4: интегральная ошибка SOC после полного цикла ≤ 5%;
  LTO: ≤ 5% по таблице.
- **AC-9.** Native-тесты (NFR-4) проходят: 10+ контрольных точек Li-ion из CSV,
  граничные точки LiFePO4/LTO.
- **AC-10.** Flash/RAM в пределах NFR-1; CI обеих веток зелёные.
- **AC-11.** Регрессия: молния зарядки, «не гасить экран на зарядке», защита
  по ADC (юг) работают как раньше; дифф файлов ядра — ноль (кроме согласованных
  в плане исключений по FR-29).

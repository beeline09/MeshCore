# Darktec Specs — SDD (Spec-Driven Development)

Работаем по схеме: **спека → согласование → план → задачи → код**.
Никакой код фичи не пишется, пока спека не согласована владельцем.

## Структура

```
docs/specs/
├── README.md                     ← этот файл (конвенция)
└── NNNN-короткое-имя/
    ├── spec.md                   ← спека: что и зачем, требования, критерии приёмки
    ├── plan.md                   ← появляется ПОСЛЕ согласования спеки
    └── tasks.md                  ← появляется после плана; чек-лист реализации
```

## Правила

1. `spec.md` — единственный источник правды по «что делаем и зачем». Меняется
   только через явное согласование (коммит с пометкой `spec:`).
2. Реализация ссылается на требования по номерам (`FR-3`, `AC-2`), чтобы
   ревью сверялось со спекой, а не с памятью.
3. Ветка/PR реализации указывает номер спеки в описании.
4. Спека живёт в репо прошивки (`docs/specs/`), между ветками переносится
   копией; сайт-часть описывается в той же спеке (раздел «Сайт»), реализуется
   в репо `beeline09.github.io`.

# WiFi→BLE fallback: сохранение WiFi-радио и фоновый повтор подключения

**Файлы:** `examples/companion_radio/MyMesh.h`, `examples/companion_radio/MyMesh.cpp`

## Проблема

При неудачном подключении к WiFi (таймаут 15 с) система переходила на BLE
и вызывала `WiFi.disconnect(true)`, полностью отключая WiFi-радио.
Повторное подключение требовало ручного входа в Settings.

## Решение

После fallback WiFi-радио **не отключается**. Каждые 30 секунд система
автоматически повторяет попытку подключения к последней выбранной сети.
При успехе интерфейс переключается обратно на WiFi без участия пользователя.

## Что изменено

### MyMesh.h
Добавлено поле `uint32_t _wifi_bg_retry_at` — timestamp следующей фоновой
попытки (0 = retry не запланирован).

### MyMesh.cpp — `checkWifiConnection()`

**Таймаут (fallback):**
- Было: `WiFi.disconnect(true)` — выключает радио
- Стало: `WiFi.disconnect(false)` — разрывает соединение, радио остаётся включённым
- Устанавливается `_wifi_bg_retry_at = millis() + 30000`

**Фоновый retry** (добавлен в начало `checkWifiConnection()`):
- Когда `_wifi_bg_retry_at` ненулевой и время наступило — запускает
  `WiFi.begin()` с теми же credentials
- Механизм success/timeout уже обрабатывается существующим кодом функции

**При успехе фонового retry:**
- `comms_mode` обновляется в `COMMS_MODE_WIFI` и сохраняется в prefs
- Интерфейс переключается с BLE на WiFi TCP

### MyMesh.cpp — `switchCommsMode()` (BLE-ветка)
При явном выборе BLE пользователем:
- `_wifi_bg_retry_at = 0` — отменяет любой запланированный фоновый retry
- `WiFi.disconnect(true)` — выключает радио (пользователь намеренно выбрал BLE)

## Поведение

| Сценарий | Поведение |
|----------|-----------|
| WiFi недоступен при старте | Fallback на BLE, retry каждые 30 с |
| WiFi появился через 2 мин | Автоматически переключится на WiFi |
| Пользователь выбрал BLE вручную | WiFi выключен, retry не запускается |
| Пользователь выбрал WiFi вручную | Обычный 15 с таймаут, затем retry |
